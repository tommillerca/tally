## 1. Ground rules that are not negotiable

- **`main` is PR-only.** Nobody pushes to `main`. Work on a branch, push the branch, open a PR, squash-merge. GitHub Pages serves `main`, so a merge is a release. After a merge, verify the live `sw.js` and `version.json` carry the new version before saying it shipped.
- **Never deploy the Worker, never run `wrangler ... --remote`, never write production D1, never set secrets.** Tom runs those. Hand him the exact commands in a fenced block.
- **Four version stamps must agree** on a release: `sw.js` VERSION, `APP_BUILD` in `js/app.js`, the newest `n:` in `js/changelog.js`, `version.json`. `tests/version-align-lint.mjs` checks it.
- **Every release claim needs proof.** `docs/CLAIMS.md` gets a `## vNNN` section per release; each PROOF names a bare test filename under `tests/`; prose in that file must not name `*.js` source files. `tests/claim-evidence-lint.mjs` enforces it.
- **A guard must be proven red.** Any new test or audit row is mutated back to the bug once and the FAIL line is quoted in the commit or report. A guard that cannot fail is not a guard. Assert sample sizes are non-zero.
- **Never read an exit code through a pipe.** `node tests/x.mjs > /tmp/x.log 2>&1; echo $? > /tmp/x.rc`. A `| tail` swallowed a red once and it was committed.
- **Browser audits need `HEADLESS_MODE=shell`.** Other headless modes hang on screenshot on this Mac. One browser lane at a time when the release gate is running; the gate is timing-sensitive.
- **One worktree per task, unique path, named branch.** `git worktree add ../scratchpad/wt-<task>-<random> -b <branch> integ/day2`. Never work in a worktree another lane is using. Symlink `node_modules` from the main checkout (`ln -s <main>/node_modules`).
- **Surgical diffs.** Touch only what the task needs. Match existing style. Dated comments explain WHY, not what. Remove imports your change orphans; do not delete other dead code (mention it).
- **Player data is sacred.** Additive migrations only; never lower a balance from a stale blob; whole-row `kvSet` of a claimed row goes through `kvUpdate` (see `tests/claimed-row-audit.mjs`).
- **Wellbeing-safe.** Nothing shames eating or rewards eating less. Nothing earned is ever permanently lost.
- **No em dashes** in anything you write.

## 2. How verification works here

- `node tests/unit.test.js` (node, ~30 s, must exit 0).
- Pure lints under `tests/*lint*.mjs` (node): run the ones your change touches, they are fast.
- Browser audits `tests/*-audit.mjs` (Puppeteer; `HEADLESS_MODE=shell node tests/<name>.mjs`). Each audit's header comment says what it protects and how it was proven red. Read it before changing an assertion.
- The release gate `HEADLESS_MODE=shell node tests/release-gate.mjs --all` runs ~255 suites over ~90 min on a **detached snapshot** (`git worktree add --detach`), never on a tree anyone is editing. Only the integrator runs it.
- A red audit is probably right. Control-run it on `origin/main` (worktree `gate4`) before calling it flaky. Classify every red as REGRESSION (fix code), DRIFT (a ruling changed the rule: fix the assertion with dated provenance), or PRE-EXISTING.
- Visual work is verified by **pixels from the real render**, never by reading CSS. Fire the real control. Animations: assert decoded pixels, not geometry.
