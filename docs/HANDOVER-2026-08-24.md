## 1. The one habit that matters here

Every expensive mistake in this project's recent history is the same shape: a
check that reported success **without examining the thing that was broken**.

Recent, real, and each one cost a day or a false claim to a player:

| what looked fine | what was actually true |
|---|---|
| An audit passing 15/15 on the friend paddock | Every row opened the sheet through a test hook. Deleting the real tap handler left all fifteen green |
| A memory suite reporting a ceiling breach | It was clicking a class that had not existed for months, with `?.` swallowing the miss, and grading a screen it never opened |
| Three lints reporting clean | The file they were grading could not be parsed by Node at all |
| A wordmark guard counting "ink pixels" | Olive art clears the brightness threshold exactly as the mark's cream does, so it counted art and concealed a real conflict |
| A patch note saying a feature shipped | It was behind a query flag no player has |

So: **verify the end of the chain, not the step you performed.** A green merge
says the code is on main. It says nothing about whether a player can reach it.

## 2. What runs, and what it costs

```
node tests/release-gate.mjs --as=<yourname>     # fast tier, minutes
node tests/release-gate.mjs --all --as=<name>   # everything, ~25 min
```

230 test files, 146 registered in the gate. Three tiers: `PURE` (node only,
instant), `BROWSER` (fast), and `DECLARED` full runs.

Two things that will bite on day one:

- **An audit on disk that the gate does not declare makes the gate exit 1 before
  a single test runs.** If the gate dies immediately, that is why.
- **`--as=<name>` claims a lock** in `CHAT-HANDOFF.md` above the repo. Two
  concurrent gate runs on one machine poison each other's timings. Contention
  biases a suite toward TIMING OUT, so a RED taken under load certifies nothing
  while a GREEN under load is credible.

`HEADLESS_MODE=shell` is forced on the owner's Mac and is itself a source of
intermittent unpainted frames. A blank-looking capture probably IS blank: reject
and retry rather than measuring it. Map suites additionally need
`--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`.

## 3. Four guards that hold the process, not the code

These are recent and deliberately mechanical, because rules get forgotten and
lints do not. Do not delete them to go faster.

- **`feedback-status-lint`** every item Tom has ever asked for carries
  OPEN / SHIPPED / DROPPED, and the open ones PRINT on every gate run.
- **`claim-evidence-lint`** every item in the newest changelog entry must be
  answered in `docs/CLAIMS.md` with PROOF (an audit that exists and the gate
  runs) and REACH (how a player gets there). `GATED`, `PENDING-DEPLOY` and
  `NEEDS-PEER` are honest answers and any of them FAILS a shipped entry.
  This exists because four patch notes in one day told players about things they
  could not see.
- **`guard-hygiene-lint`** carries three ratchets: audits with no positive
  control, audits Node cannot parse, and audits that only ever touch a test hook.
- **`guard-provenance-lint`** a pinned expectation constant must cite a dated
  source. A number with no method behind it is not evidence.

## 5. Measuring what a branch actually contains

Three-dot diffs and `git merge-tree` both lie, and both lied to me this week.

- `git diff main...branch` diffs from the MERGE BASE, so work already shipped
  under another PR still looks new.
- `git merge-tree` on a conflicting branch returns a tree full of conflict
  markers, so diffing it counts `<<<<<<<` as content.

The honest answer is a real merge in a throwaway worktree, then
`git diff --cached --stat`. A branch that "adds 420 lines" was, measured properly,
a stale draft that would have reverted a shipped fix.

## 6. Prove-red discipline, and two traps in it

Every guard row must be shown to FAIL on the real defect before you trust it.

1. **`cp -R` of a git WORKTREE is not isolated.** The copy's `.git` is a file
   pointing back at the original, so `git checkout <ref> -- path` inside it writes
   somewhere else and your prove-red passes while proving nothing. Build throwaway
   trees with `tar` excluding `.git`, mutate the FILE directly, and grep the copy
   to confirm the mutation landed.
2. **If your revert also removes a test SEAM the audit needs**, the audit fails
   for the wrong reason while its real rows pass green. Isolate the defect from
   the harness: disable only the fix, keep the seam.
