## THE LESSON OF THE DAY, worth more than the feature list

**Four separate guards reported GREEN while unable to see the bug they existed
for.** All four were mine, not the app's:

1. a case appended below `await runAll();` in unit.test.js registered into an
   already-drained queue and never ran
2. a CSS check that required a `}` before its selector silently graded a
   different rule
3. a mutation-based prove-red where the mutation may not have applied, because
   nothing asserted that it had
4. an audit that searched for "the app named an ingredient the player did not
   get" **among the ingredients the player already owned**, a set that by
   definition cannot contain the lie

None would have been caught by running the tests. Only by insisting they fail
first. Before calling any guard proven, ask what it would look like if it were
blind, and rule that out.

Related: the repaired release gate found FOUR real problems on its first run
after being unblocked, including two that had been red on main for months and a
genuine CSS regression in the release itself.
